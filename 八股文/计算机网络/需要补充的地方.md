## 二、缺漏内容补充优先级划分

### ⭐ 第一优先级：必背高频考点（面试 80% 概率考，必须补充）

这部分是 HTTP/HTTPS 面试的核心必问题，你的笔记里没有覆盖，是短时备考的重中之重。

表格

|缺漏内容|补充到笔记的对应位置|面试核心考点（直接背）|
|:--|:--|:--|
|HTTP 核心常见字段|HTTP 简述与特性|必须掌握`Host`/`Connection`/`Content-Type`/`Content-Length`/`Cache-Control`/`ETag`/`If-Modified-Since`的作用，面试常单独追问单个字段的含义与场景|
|GET 和 POST 的安全与幂等性|GET 和 POST 的区别|面试必追问：<br><br>1. GET 是只读的，安全且幂等；POST 会修改资源，不安全且不幂等<br><br>2. 幂等性的定义：多次执行相同请求，结果和副作用完全一致|
|HTTP 与 HTTPS 的核心区别、HTTPS 解决的 HTTP 问题|HTTPS 部分|面试必问：<br><br>1. 核心区别：HTTP 明文传输、HTTPS 加密传输，默认端口 80 vs 443<br><br>2. HTTPS 解决了 HTTP 的 3 个核心问题：窃听风险（加密）、篡改风险（完整性校验）、冒充风险（数字证书）|
|数字证书、CA 机构、证书验证流程|HTTPS 部分|HTTPS 的信任核心，面试必问：<br><br>1. 证书是 CA 机构签发的，用来证明服务端身份，防止中间人攻击<br><br>2. 客户端验证证书：校验证书的有效期、CA 签名、域名是否匹配|
|HTTPS RSA 握手完整流程（TLS 四次握手）|HTTPS 建立连接的流程|面试常让你口述 / 画图 TLS 握手的每一步：<br><br>1. 客户端发 Client Hello（随机数 1、支持的加密套件）<br><br>2. 服务端回 Server Hello（随机数 2、选定加密套件）+ 服务器证书 + Server Hello Done<br><br>3. 客户端验证证书，生成预主密钥，用服务端公钥加密后发送<br><br>4. 双方用随机数 1/2 + 预主密钥生成会话密钥，客户端发 Finished<br><br>5. 服务端验证后发 Finished，握手完成，用对称密钥传输数据|
|HTTP/1.1、HTTP/2、HTTP/3 跨版本核心对比|HTTP 版本演变|面试常问三个版本的核心差异，重点记：<br><br>1. HTTP/1.1：长连接但有队头阻塞，明文传输<br><br>2. HTTP/2：二进制帧、多路复用解决应用层队头阻塞，头部压缩，服务器推送<br><br>3. HTTP/3：基于 UDP 的 QUIC 协议，彻底解决传输层队头阻塞，0-RTT 握手，连接迁移|

### ⭐⭐ 第二优先级：次高频拉分考点（大厂必问，中小厂高频追问，建议补充）

这部分是进阶考点，用来和其他候选人拉开差距，短时备考先记核心结论，不用抠细节。

表格

|缺漏内容|补充到笔记的对应位置|面试核心考点|
|:--|:--|:--|
|HTTP/1.1 的性能优化方案|HTTP/1.1 的不足|面试常问「如何优化 HTTP 请求」，核心记 3 点：<br><br>1. 避免请求：用好缓存<br><br>2. 减少请求：合并请求、减少重定向、延迟请求<br><br>3. 减少响应体积：资源压缩|
|HTTP 队头阻塞的完整演进|HTTP 版本演变|面试高频跨版本追问：<br><br>1. HTTP/1.1：同一 TCP 连接，前一个请求没响应，后面的请求会被阻塞（队头阻塞）<br><br>2. HTTP/2：多路复用解决了应用层的队头阻塞，但 TCP 丢包依然会阻塞整个连接<br><br>3. HTTP/3：基于 UDP 的 QUIC，流之间独立，彻底解决队头阻塞|
|HTTPS 性能优化手段|HTTPS 部分|大厂常问，核心记：<br><br>1. 会话复用：Session ID / Session Ticket，复用之前的会话密钥，省去完整握手<br><br>2. 证书优化：OCSP Stapling，服务端提前带上证书吊销状态，省去客户端查询时间<br><br>3. 协议升级：TLS 1.3，握手更快，加密套件更安全|
|HTTP/2 核心优化细节|HTTP/2 相较 1.1 的改进|面试常问「HTTP/2 为什么比 1.1 快」，核心记：<br><br>1. 二进制帧：传输更高效，解析更简单<br><br>2. 多路复用：同一 TCP 连接并行传输多个流，互不阻塞<br><br>3. HPACK 头部压缩：减少重复头部的传输体积<br><br>4. 服务器推送：主动给客户端推送资源，不用客户端请求|
|HTTP vs RPC|新增独立小节|后端开发面试高频，核心记：<br><br>1. HTTP 是通用协议，RPC 是服务间调用的定制化协议<br><br>2. RPC 传输效率更高、序列化更灵活、服务治理能力更强（熔断、限流、负载均衡）<br><br>3. 浏览器场景用 HTTP，微服务内部服务调用用 RPC|
|HTTP vs WebSocket|新增独立小节|面试常问，核心记：<br><br>1. HTTP 是半双工，一问一答；WebSocket 是全双工，建立连接后双方可以随时发数据<br><br>2. WebSocket 解决了 HTTP 轮询的性能问题，适合实时通信场景（聊天、直播、实时看板）|
