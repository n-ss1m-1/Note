## 一、TCP / UDP（最高频，必问）

### 文档原题

1. UDP 和 TCP 区别
2. TCP 三次握手、四次挥手
3. TCP 流量控制、拥塞控制
4. TCP 可靠性、顺序性如何保证
5. TCP 粘包问题、怎么解决
6. 知道 IP + Port 就能建立 TCP 连接吗？连接建立流程
7. TCP 如何保证可靠传输
8. 大量 CLOSE_WAIT 如何排查

### 高频核心知识点

1. **TCP vs UDP**
    
    - 连接、可靠、有序、面向字节流 / 无连接、不可靠、无序、面向报文
    - 使用场景：HTTP / 文件传输 / 视频、直播、DNS
    
2. **三次握手（重点）**
    
    - 目的：同步序列号、防止失效连接、避免资源浪费
    - 状态：CLOSED → SYN_SENT → SYN_RCVD → ESTABLISHED
    
3. **四次挥手（重点）**
    
    - 为什么需要四次：双向独立关闭
    - FIN_WAIT1、FIN_WAIT2、TIME_WAIT、CLOSE_WAIT
    
4. **TIME_WAIT 作用与危害**
    
    - 确保对方收到 FIN、防止旧报文干扰、2MSL 原因
    
5. **可靠性保证**
    
    - 校验和、序列号、确认应答、超时重传、滑动窗口
    
6. **流量控制（滑动窗口）**
    
    - 接收方告诉发送方自己缓冲区大小
    
7. **拥塞控制（必考）**
    
    - 慢启动、拥塞避免、快重传、快恢复
    
8. **TCP 粘包 / 拆包**
    
    - 原因：TCP 是流协议
    - 解决：固定长度、分隔符、消息头 + 长度
    

### 高频扩展面试题

- 为什么不能两次握手？为什么要三次？
- 挥手为什么要四次？
- TIME_WAIT 过多怎么优化？
- CLOSE_WAIT 过多是什么原因？
- SYN 洪水攻击是什么？怎么防御？

## 二、HTTP / HTTPS（高频）

### 文档原题

1. 访问一个网站流程（HTTP 视角）
2. HTTP 状态码
3. HTTP1.0 / 1.1 / 2.0 / 3.0 区别
4. HTTP 和 HTTPS 区别
5. 分块传输、Nagle 算法、MTU

### 高频核心知识点

1. **URL 输入到页面展示全过程（必背）**
    
    - DNS → TCP → TLS → 请求 → 响应 → 渲染
    
2. **HTTP 状态码**
    
    - 200、301、302、304、400、401、403、404、500、502
    
3. **HTTP 1.0 / 1.1 / 2.0 / 3.0**
    
    - 1.1：长连接、管道化、缓存
    - 2.0：多路复用、头部压缩、服务器推送、二进制
    - 3.0：QUIC、UDP、0-RTT、解决队头阻塞
    
4. **HTTPS 流程**
    
    - 非对称加密交换密钥 → 对称加密传输数据
    - CA 证书、数字签名、防篡改
    
5. **缓存机制**
    
    - 强缓存：Cache-Control、Expires
    - 协商缓存：Last-Modified、ETag
    

### 高频扩展面试题

- HTTPS 是如何保证安全的？
- HTTP 2.0 多路复用原理？
- 304 响应过程？
- GET 和 POST 区别？

## 三、IO 多路复用（select /poll/epoll）高频

### 文档原题

1. select、poll、epoll 区别
2. epoll 工作流程
3. IO 密集时 epoll 效率还高吗
4. ET 模式

### 高频核心知识点

1. **select**
    
    - 最大文件描述符限制、遍历全量、用户态拷贝
    
2. **poll**
    
    - 无最大限制、仍遍历、链表存储
    
3. **epoll（重点）**
    
    - 事件驱动、回调机制、内核缓存、无遍历
    - LT 水平触发 / ET 边沿触发
    
4. **epoll 高效原因**
    
    - 减少拷贝、减少遍历、事件通知
    

### 高频扩展面试题

- 边缘触发 ET 为什么必须配合非阻塞？
- epoll 惊群效应？
- 高并发为什么用 epoll？

## 二、面试高频知识点汇总（优先级从高到低）

### 1. 传输层（核心中的核心）

- TCP 三次握手 / 四次挥手：
    
    - 核心问题：为什么三次握手（防止历史连接）、为什么四次挥手（半关闭状态）、SYN 泛洪攻击原理及防范；
    - 延伸：半连接队列、TIME_WAIT 状态的作用。
    
- TCP 可靠传输机制：
    
    - 滑动窗口（流量控制）、确认重传（序列号 / 确认号）、超时重传、拥塞控制（慢开始→拥塞避免→快重传→快恢复）。
    
- TCP vs UDP 对比：
    
    - 核心维度：连接性、可靠性、报文 / 字节流、开销、适用场景（TCP：文件传输 / 支付；UDP：直播 / 视频 / 游戏 / DNS）。
    
- 端口号的作用：标识应用进程，实现 “端到端” 通信。

### 2. 应用层

- HTTP/HTTPS：
    
    - HTTPS 加密流程（非对称加密协商密钥 + 对称加密传输数据）、CA 证书的作用（防中间人攻击）；
    - HTTP 版本差异：HTTP1.1（长连接 / 管线化）、HTTP2.0（多路复用 / 二进制帧）、HTTP3.0（QUIC 协议，基于 UDP）；
    - GET vs POST 区别：语义（查 / 改）、参数位置、缓存、幂等性、安全性。
    
- DNS 协议：
    
    - 递归查询（客户端→本地 DNS）vs 迭代查询（本地 DNS→根服务器）；
    - 为什么同时用 UDP（轻量）和 TCP（大数据包 / 区域传输）。
    

### 3. 网络层

- 子网划分 / 子网掩码计算：
    
    - 经典题：如 192.168.1.0/24 划分为 4 个子网，求子网掩码、可用 IP 范围。
    
- ARP 协议：
    
    - 原理（广播请求、单播响应）、ARP 欺骗（伪造 MAC 地址）、ARP 缓存。
    
- IPv6：
    
    - 核心优势（地址空间大、无 NAT、内置安全、简化报头）。
    
- NAT：解决 IPv4 地址耗尽，端口映射（NAT-PT）。

### 4. 数据链路层

- CSMA/CD 原理：以太网的冲突处理机制。
- 冲突域 / 广播域：
    
    - 集线器（Hub）：一个冲突域 + 一个广播域；
    - 交换机：多个冲突域 + 一个广播域；
    - 路由器：多个冲突域 + 多个广播域。
    
- VLAN：隔离广播域，提升网络安全性和效率。

### 5. 物理层（低频）

- 奈奎斯特 / 香农定理计算：如给定带宽、信噪比，求最大传输速率。

## 三、经典面试题示例（对应高频考点）

### 传输层

1. 为什么 TCP 建立连接需要三次握手，关闭连接需要四次挥手？
2. 简述 TCP 拥塞控制的完整流程（慢开始、拥塞避免、快重传、快恢复）。
3. UDP 的不可靠体现在哪里？为什么直播 / 游戏优先用 UDP？

### 应用层

1. HTTPS 的完整加密流程是什么？为什么需要 CA 证书而不是直接用非对称加密传输数据？
2. HTTP1.1 相比 HTTP1.0 的核心改进？HTTP2.0 的多路复用解决了什么问题？
3. 从幂等性、缓存、安全性角度，说明 GET 和 POST 的区别。

### 网络层

1. 给定 IP 地址 192.168.2.0/24，要求划分出至少 6 个子网，求每个子网的子网掩码、网络地址和可用 IP 范围。
2. ARP 欺骗的原理是什么？如何防范 ARP 攻击？

### 数据链路层

1. CSMA/CD 的工作流程是什么？适用于哪种拓扑结构？
2. 交换机和集线器的核心区别？为什么交换机能隔离冲突域？
